# MVoxel

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![.NET](https://img.shields.io/badge/.NET-10.0-512BD4)](https://dotnet.microsoft.com/)
[![Platform](https://img.shields.io/badge/Platform-Windows%20x64-0078D4)](#构建与发布)

MVoxel 是一个面向创作者的体素建模与渲染编辑器。它使用纯色体素和材质属性构建场景，并提供场景编辑、实时渲染、项目模板、插件和命令行工具。

## 快速开始

1. 下载并解压绿色版，双击 `MVoxel.exe`。绿色版自带 .NET 运行时，不需要另装 .NET。
2. 在欢迎界面选择“新建项目”或“打开项目”。
3. 进入场景后，在层级中选择对象；右侧检查器用于编辑对象名称、坐标和组件。
4. 在场景中使用左键放置、右键环绕、中键平移；普通模式下使用 `Shift+左键` 破坏。开启大小写锁定后，左键放置、右键破坏、`Shift` 加速，鼠标移动视角，中键仍用于平移；编辑器设置中的 MC 模式会反转大小写锁定后的左右键功能。
5. 使用“项目 → 保存项目”保存场景和项目配置。

第一次使用可以从欢迎界面的引导开始，十分钟走完建项目、画方块、出渲染图、保存的完整流程；Minecraft 存档、`.vox`、`.schem` 等导入入口都在“文件”菜单里。

制作绿色版：双击仓库根目录的 `打包绿色版.bat` 即可，脚本会自动执行 Windows x64 自包含发布再打包 ZIP，不需要先手动编译。包内自带 .NET 运行时，用户完整解压后直接双击 `MVoxel.exe` 就能用。初始压缩包不包含个人项目、配置和缓存；程序默认把编辑器配置、缓存和日志写入 `%LocalAppData%\MVoxel`。需要真正便携运行时，可使用 `MVoxel.exe --portable`，或在程序目录放置空文件 `MVoxel.portable`，此时数据写入程序目录的 `MVoxelData`。旧版本程序目录中的 `MVoxelData` 会在首次默认启动时复制到新的用户数据目录，原目录保留不删除。

打包不会在仓库里生成发布副本：自包含发布先写到系统临时目录 `%TEMP%\MVoxel-portable-stage`，压缩完成即删除，运行被中断留下的半成品也会在下次打包时清空。仓库根目录只留 ZIP，`打包绿色版.bat` 默认保留最近 5 个，更早的会在下次打包成功后被删除；想一次看清将要做什么，可以运行 `powershell -File tools\package-portable.ps1 -PlanOnly`。构建中间产物仍在 `MVoxel\obj` 与 `MVoxel\bin` 下，需要清理时用 `dotnet clean` 或手动删除；`MVoxel\bin\Release\net10.0-windows\MVoxelData` 是便携运行时的数据目录，可能包含配置、缓存和日志，删除前请先确认。

MVoxel 的主要工作对象是场景和预制体。对象默认带有坐标组件，再按需要添加模型、光照或相机组件；体素数据文件属于内部数据，由这些对象和组件使用，不需要单独理解文件格式才能开始创作。

## 文档

程序内置了快速入门与帮助文档，可从欢迎界面和“帮助”菜单打开，内容随程序版本更新。仓库根的 `Docs/` 是作者私有笔记与开发计划，不随公开仓库分发。

推荐上手顺序：先跟欢迎界面的引导走完第一个作品，再看程序内“帮助 → 入门教程”了解项目文件、材质、渲染、生成器与插件；从 MagicaVoxel 迁移时，重点看 `.vox` 导入导出与材质映射的差异说明。

## 构建与发布

```powershell
dotnet build .\MVoxel.sln --no-restore --configuration Release -m:1
dotnet publish .\MVoxel\MVoxel.csproj --configuration Release --runtime win-x64 --self-contained true --output .\artifacts\publish\MVoxel
```

未显式指定配置时，项目和解决方案默认使用 `Release`；`Debug` 仅保留给具体项目的显式调试构建。编辑器采用常规 .NET JIT 发布，不启用裁剪或 NativeAOT，以保留插件、脚本和反射式检查器能力。绿色版按 `win-x64` 自包含发布，发布目录里的运行时文件和原生依赖一起打包，用户不需要安装 .NET；日常开发构建仍是框架依赖，运行时安装一次即可。

按项目所有者要求，已移除测试源码项目和解决方案引用，不再新增或运行自动化测试、烟测及性能台架；开发阶段执行构建和代码检查，实际功能与体验由用户验收。构建成功不代表功能验收通过。
