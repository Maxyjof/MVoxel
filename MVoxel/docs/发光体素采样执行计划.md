# 发光体素采样执行计划

## 目标与约束

让路径追踪中的小型及多处发光体更有效地照亮场景，保持颜色、材质、遮挡、原生数据精度与现有实时视图。光源索引是可重建的运行时数据，不改变文件格式。不得通过降低分辨率、模型精度或相机导航效果换取性能。每阶段更新本文、使用文档，检查构建与 `git diff --check`，只清理本阶段确认产生的临时文件，单独提交。项目所有者负责实际功能和体验验收；不新增或运行自动化测试、烟测或性能台架。

## 现状与验收依据

- [x] 核对 Compute 路径：发光体素通过射线命中贡献发光，已接入发光面直接采样；实时模式只显示自身发光。
- [x] 核对光源结构：场景本地灯与发光体素分别处理；已有几何 BVH、砖驻留和脏区更新，并有独立的发光面索引。
- [x] 核对已知限制：发光贡献被钳制，低概率命中小灯时可能收敛慢；快速降噪不能代替采样。未经实际测量，不断言主要性能瓶颈或收益。
- [x] 建立可复现的人工比较说明（见《LightBVH评估与人工验收》；实际结果待用户记录）：同一相机、分辨率、反弹和采样设置，比较小灯、密集彩灯、遮挡、暗弱灯、发光材质改动、跨区块编辑及空场景；记录收敛观感、更新耗时、帧时间和显存，标明硬件。由用户实际操作验收，不创建自动化测试或台架。

## 阶段一：先澄清当前功能

- [x] 对照 Shader 修正太阳直接光开关名称、字段、提示和开发注释。
- [x] 文档解释发光体素依赖射线命中、实时与路径模式的差异、当前钳制与收敛限制。
- [x] 检查设置入口一致性，构建、检查差异并提交；应用内功能和体验由用户验收。

## 阶段二：发光面数据基础

- [x] 建立 CPU 发光面目录原型：以 64 位世界坐标和单位面方向保存原始颜色、材质槽与标志；按脏区块及六邻区重建。当前仅收集不透明发光体邻格为空的面；已接入 GPU 与渲染，其他面保留命中发光。
- [x] 设计运行时发光面记录：局部坐标、法线、面积、颜色、材质槽和选取概率；明确贪心盒、砖路径及 64 位世界锚点的坐标换算。
- [x] 从完整世界及实际渲染可见性提取可采样面；处理不透明、半透明、相邻发光体、遮挡及区块边界，不丢失弱光或原始数据。明确哪些面不可采样且保留命中贡献。
- [x] 处理体素、邻区、材质、颜色和全局设置变化；为零灯、容量不足、全量重建和设备资源释放定义安全行为。
- [x] 完成 CPU/GPU 数据布局及同步，确保不会读到过期记录；记录更新成本；构建、文档、提交。

## 阶段三：简单发光面直接采样

- [x] 所有者已决定：同时校正 BSDF 采样、路径权重与 MIS，确保概率一致性。
- [x] 将反弹改为固定材质分支概率的 GGX NDF / 余弦半球混合，按完整 BRDF 和混合 PDF 更新路径权重；此步仍不包含发光面 NEE 或 MIS。C# 构建与差异检查通过，运行时 Shader 和画面待验收。
- [x] 修复更新边界：材质表保存独立快照，实际变动清除累积；砖驻留仅在同一世界实例中复用增量结构。构建通过，实际交互待用户验收。
- [x] 建立可计算精确 PDF 的基线分布，先在路径追踪的漫反射表面采样发光面、采样面上位置并投射有界阴影射线。
- [x] 正确处理距离、双方余弦、面积到立体角 PDF 的转换、零概率、近距离、自相交、遮挡及数值退化。
- [x] 对可由 NEE 和 BSDF 双方命中的发光面应用一致 MIS；直接可见光、镜面、透明路径和不可采样光源保持正确贡献。审视既有发光钳制及关闭自发光的语义，避免重复亮度或能量丢失。
- [x] 场景或材质变化重置累积；保持实时模式和本地灯行为；说明硬件 RT 功能范围与回退。构建、文档、提交，交用户验收。

光源树与均匀采样已实现并可切换。具体结构、成本与人工验收条件见《LightBVH评估与人工验收》，不以编译结果替代性能证据。

- [ ] 基于阶段三实现和用户场景判断是否需要 Light BVH；比较简单分布和分层采样的画质收敛、更新和帧成本，不把论文数字当项目结论。
- [x] 按空间砖排序和功率构建平衡光源树；支持接收点重要性与精确选择 PDF，光源少时保留简单路径；不排除弱光。
- [x] 实现脏区与邻区目录刷新、材质更新后 refit、面集合变化重建、容量增长、空树和脏范围上传；保持几何 BVH 独立。分配或上传失败由渲染错误路径报告，不静默使用过期索引。
