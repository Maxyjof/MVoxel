# 发光体素采样执行计划

## 目标与约束

让路径追踪中的小型及多处发光体更有效地照亮场景，保持颜色、材质、遮挡、原生数据精度与现有实时视图。光源索引是可重建的运行时数据，不改变文件格式。不得通过降低分辨率、模型精度或相机导航效果换取性能。每阶段更新本文、使用文档，检查构建与 `git diff --check`，只清理本阶段确认产生的临时文件，单独提交。项目所有者负责实际功能和体验验收；不新增或运行自动化测试、烟测或性能台架。

## 现状与验收依据

- [x] 核对 Compute 路径：发光体素通过射线命中贡献发光，目前没有发光面直接采样；实时模式只显示自身发光。
- [x] 核对光源结构：场景本地灯与发光体素分别处理；已有几何 BVH、砖驻留和脏区更新，但没有可抽样发光面索引。
- [x] 核对已知限制：发光贡献被钳制，低概率命中小灯时可能收敛慢；快速降噪不能代替采样。未经实际测量，不断言主要性能瓶颈或收益。
- [ ] 建立可复现的人工比较说明：同一相机、分辨率、反弹和采样设置，比较小灯、密集彩灯、遮挡、暗弱灯、发光材质改动、跨区块编辑及空场景；记录收敛观感、更新耗时、帧时间和显存，标明硬件。由用户实际操作验收，不创建自动化测试或台架。

## 阶段一：先澄清当前功能

- [x] 对照 Shader 修正太阳直接光开关名称、提示和开发注释；保留序列化字段和既有行为。
- [x] 文档解释发光体素依赖射线命中、实时与路径模式的差异、当前钳制与收敛限制。
- [x] 检查设置入口一致性，构建、检查差异并提交；应用内功能和体验由用户验收。

## 阶段二：发光面数据基础

- [x] 建立 CPU 发光面目录原型：以 64 位世界坐标和单位面方向保存原始颜色、材质槽与标志；按脏区块及六邻区重建。当前仅收集不透明发光体邻格为空的面，尚未接入渲染或 GPU，也未改变现有画面；其他面仍须保留命中发光。
- [ ] 设计运行时发光面记录：局部坐标、法线、面积、颜色、材质槽和选取概率；明确贪心盒、砖路径及 64 位世界锚点的坐标换算。
- [ ] 从完整世界及实际渲染可见性提取可采样面；处理不透明、半透明、相邻发光体、遮挡及区块边界，不丢失弱光或原始数据。明确哪些面不可采样且保留命中贡献。
- [ ] 处理体素、邻区、材质、颜色和全局设置变化；为零灯、容量不足、全量重建和设备资源释放定义安全行为。
- [ ] 完成 CPU/GPU 数据布局及同步，确保不会读到过期记录；记录更新成本；构建、文档、提交。

## 阶段三：简单发光面直接采样

- [x] 所有者已决定：同时校正 BSDF 采样、路径权重与 MIS，接受旧场景亮度和材质外观变化，不以保留近似外观替代概率一致性。
- [x] 修复更新边界：材质表保存独立快照，实际变动清除累积；砖驻留仅在同一世界实例中复用增量结构。构建通过，实际交互待用户验收。
- [ ] 建立可计算精确 PDF 的基线分布，先在路径追踪的漫反射表面采样发光面、采样面上位置并投射有界阴影射线。
- [ ] 正确处理距离、双方余弦、面积到立体角 PDF 的转换、零概率、近距离、自相交、遮挡及数值退化。
- [ ] 对可由 NEE 和 BSDF 双方命中的发光面应用一致 MIS；直接可见光、镜面、透明路径和不可采样光源保持正确贡献。审视既有发光钳制及关闭自发光的语义，避免重复亮度或能量丢失。
- [ ] 场景或材质变化重置累积；保持实时模式和本地灯行为；说明硬件 RT 功能范围与回退。构建、文档、提交，交用户验收。

## 阶段四：多光源分层采样

- [ ] 基于阶段三实现和用户场景判断是否需要 Light BVH；比较简单分布和分层采样的画质收敛、更新和帧成本，不把论文数字当项目结论。
- [ ] 如有价值，按空间邻近和功率构建光源砖及树；支持接收点重要性与精确选择 PDF，光源少时保留简单路径；不排除弱光。
- [ ] 设计局部更新、区块边界及材质变动失效，容量增长、空树、设备恢复和构建失败回退；保持几何 BVH 独立。
- [ ] 验证选择 PDF 与 BSDF 命中 PDF 一致，检查动态编辑时闪烁和累积清除；构建、文档、提交，交用户验收。

## 阶段五：整合与验收

- [ ] 根据实际结果评估降噪、钳制及阴影射线预算；不默认引入 ReSTIR、可见性复用或降分辨率。
- [ ] 整理用户文档、控件悬停说明、已知限制和兼容性；检查渲染、导出、相机导航与保存行为。
- [ ] 用户在实际应用中验收画质与交互；记录尚未验收项目，不将编译通过称为功能验证。清理确认的临时文件，保留用户资产、配置、日志、恢复数据及 Release 输出；最终检查并提交。
