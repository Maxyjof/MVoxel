# 天气与表面覆盖：实现调研

本记录用于后续设计，不代表这些功能已经在 MVoxel 中实现。

## 参考与适用性

- [MagicaVoxel 渲染参考](https://leonida.gitbooks.io/magicavoxel-user-reference-manual/content/rendering.html)列出太阳、天空及雾的渲染控制，未以此推断它提供完整天气模拟。
- [Luanti 粒子实现](https://github.com/luanti-org/luanti/blob/master/src/client/particles.cpp)将位置、速度、加速度和寿命作为粒子状态，并可选择碰撞及碰撞后移除。它适合作为体素场景中粒子与几何交互的参考；MVoxel 的时间轴还要求任意帧可重复求值，不能简单依赖逐帧积分历史。
- [voxolith 的降水着色器](https://github.com/voxolith/renderer/blob/f6c0bcdf81f8816ca3be9b076ed54234442d5bb2/src/shaders/precip.wesl)使用世界空间随机场和视线深度分层，按首个表面距离遮挡；其[表面着色](https://github.com/voxolith/renderer/blob/f6c0bcdf81f8816ca3be9b076ed54234442d5bb2/src/shaders/raymarch.wesl)还区分湿润和朝上表面的积雪，并对遮蔽做向上查询。该实现的分层采样是近似，并非完整粒子模拟，也不应直接套用其距离和尺寸。
- [Godot 粒子文档](https://docs.godotengine.org/en/stable/tutorials/3d/particles/properties.html)区分局部和世界坐标，并说明可见包围盒过小会造成粒子突然消失；[固定种子](https://docs.godotengine.org/en/stable/classes/class_gpuparticles3d.html)用于可重现的模拟。[Unreal Niagara](https://dev.epicgames.com/documentation/unreal-engine/caching-and-reusing-your-system)同样强调确定性种子以及时间轴回放的一致性。
- [Unity 投射贴花](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@14.0/api/UnityEngine.Rendering.Universal.DecalProjector.html)包括投射范围、角度衰减、距离和图层；[Unity 贴花材质](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/prebuilt-shader-graphs-urp-decal.html)允许分别影响颜色、法线及光滑度，湿表面可以主要改变光滑度。[Godot 贴花](https://docs.godotengine.org/en/stable/tutorials/3d/using_decals.html)还提供投射深度、上下衰减和接收层。贴花不增加真实几何厚度；积雪外轮廓需要另行设计，不能宣称贴花能堆高体素。

## 对 MVoxel 的设计约束

1. 天气状态以场景参数、整数种子和时间轴采样时刻为输入；暂停保持当前帧，倒退、跳帧和导出同帧得到一致结果。雨雪可同时存在，风使用世界方向，镜头移动不能带动雨雪。
2. 雨雪需要按场景表面深度遮挡，屋檐遮蔽与碰撞应明确为独立能力；不能把视线遮挡误称为屋顶遮雨。实时和路径追踪均需覆盖，透明表面的行为须明确。
3. 贴花组件以对象变换确定投射体积和方向，参数应覆盖启用、范围、边缘及深度衰减、表面角度、接收图层、遮罩、强度和排序；积水需控制颜色与粗糙度等材质响应，积雪需控制颜色、覆盖率及朝向。覆盖在表面着色阶段参与，而非仅给已完成画面染色。
4. 天气和贴花的范围、粒子密度与渲染工作量应可解释、可调；不得通过自动降低分辨率、模型精度或导航光照掩盖性能问题。截图需标明场景、帧和参数。
5. 首次载入时编译大型着色器和创建 Vulkan 管线可能阻塞 UI：2026-11-05 的日志记录首帧预览管线创建约 24.5 秒。主 Compute 管线和 Ray Query 变体已改为后台编译与建管线，关闭或设备重建时等待后台任务结束后再释放设备；效果尚待用户实际验收，关闭期间等待驱动完成仍可能耗时。撤回的空间雨雪试验尚未证明可用。

积水、积雪的组件数据和序列化标识已经建立；投射数据已接入场景、渲染和导出管线，在表面着色时影响颜色、粗糙度及法线，组件已开放添加菜单与检查器。接收图层已接入场景和导出数据路径；运行画面和交互尚未验收，不能视为功能完成。

接收图层的数据准备采用独立的临时坐标映射，按场景合成相同的可见性、图层和重叠顺序记录最终归属，不修改原生体素值。快照构建前后检查源世界引用和内容版本，检测到变化时拒绝返回混合结果。坐标映射转换为相对工作集原点的开放寻址表，追加到投射缓冲中，着色器按命中坐标查询并筛选。只在存在受限掩码时构建该表；导出任务保存独立快照。解析地面没有对象图层，仅全层掩码接收投射。

接收层缓存同时检查场景渲染状态、对象体素世界引用及其内容版本；组合世界缓存显式失效时也清除接收层缓存，避免沿用旧对象归属。场景视口和不同相机遮罩使用各自的有限缓存条目，避免交替渲染时反复构建同一张表。

以上是独立实现的设计参考，不将第三方源码直接复制到项目中。许可证和版本应在实际引入任何第三方代码或资产前单独核对。
